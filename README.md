# HistoryMemo

Short life-story questions. The storyteller hears each one in **English, Vietnamese, Japanese or Teochew
(Tiếng Tiều / 潮州話)**, taps one big button, and answers by **video** (default) or **voice**.
Every story is saved to **Google Drive, organised by user**, and compiled into a **biography book** and a **video biography**.

**The journey**

| Step | What is asked | Where it's saved |
|---|---|---|
| 1. **56 life questions** | Fixed, hand-written (`apps-script/Questions.gs`), 8 themes | `Week 01 – Childhood/` … |
| 2. **Life timeline** | Generated by the **Claude API**, in order from birth → childhood → teens → young adult → middle years → later years → today, building on what they already told (4 per stage) | `Timeline 1 – Born/` … |
| 3. **Diary** | Short daily prompts ("What happened today?", "A story you never told us") | `Diary 2027-03/` … |
| 📖 **Book** | Admin → *Make book*: Google Doc ordered **from family roots and birth to today**, each story with date, language, link and transcript; optional AI-written chapter per life stage | `The Life of Ba` (Google Doc → download as PDF/Word) |
| 🎬 **Video book** | `npm run video-book`: all clips in life order with chapter and question title cards | `video-book-vi.mp4` |

- **Pace:** 1, 2, 3 or 5 questions a day (reminders spread over the day) and **"answer one more now"** any time. Progress
  follows answers, not the calendar, so going faster or skipping days is fine.
- **Life order:** every question has a life stage. After recording, the storyteller can tap *"When did this happen?"*
  (before I was born / childhood / teens / 20–35 / 35–60 / 60+ / now) so diary stories land in the right chapter.
- **Several languages?** The question language rotates: **one language per day**, or **switching with every question**.
  Hearing questions in different languages helps bring back different memories.
- **Login:** *Sign in with Google*, or a **private link** for elders without email (made by family on the admin page).
- **Reminders:** a notification pops up on the iPhone at the person's local time (1–3 times a day).

```
Phone (home-screen web app) ──► Vercel API (/api/*) ──► Google Apps Script ──► Google Drive / Shared Drive
     │  video/audio upload goes straight to Drive ────────────────────────────►  HistoryMemo/<user>/<week>/
     ◄── daily notification ◄── /api/push ◄── hourly Apps Script trigger
```

## 1 · Run it locally first (no accounts needed)

Requirements: **Node 18+**, VS Code.

```bash
npm install
npm run dev:mock
```

- App: <http://localhost:3000> → **Local demo** → choose languages → record.
- Admin: <http://localhost:3000/admin.html?a=local-admin> → add storytellers, record Teochew question voices.
- Files: <http://localhost:3000/__drive>, also on disk in `local-data/drive/Shared drive/HistoryMemo/<user>/…`

`dev:mock` runs the **real** Apps Script code (`apps-script/*.gs`) with Google's services simulated on your disk,
so what you see locally is how Google Drive will be organised. Use Chrome/Safari on your Mac; camera and mic work on `localhost`.

## 2 · Accounts you need for the real version (all free to start)

| Account | Used for |
|---|---|
| **GitHub** | Code repository (push from VS Code: Source Control → *Publish to GitHub*, private) |
| **Vercel**, signed up *with GitHub* | Hosting `historymemo.vercel.app` + the notification sender |
| **Google account**: the "owner" | Owns the Apps Script and the Drive where all stories are stored. **Shared Drive** needs Google Workspace (~US$7/user/month); a free Gmail works with a normal Drive folder |
| **Google Cloud project** (same Google account) | Only for the *Sign in with Google* button (an OAuth Client ID, free) |

Storytellers need nothing but a phone. Family members who sign in with Google get their own storyteller account.

## 3 · Google Apps Script (Drive backend)

1. <https://script.google.com> → **New project** → name it `HistoryMemo`.
2. Create two files and paste: `apps-script/Code.gs` and `apps-script/Questions.gs` (＋ → Script).
3. ⚙ Project Settings → tick *Show appsscript.json* → paste `apps-script/appsscript.json`.
4. In `Code.gs` → `CONFIG`:
   - `APP_URL`: your Vercel URL (Step 5), e.g. `https://historymemo.vercel.app`
   - `SHARED_DRIVE_ID`: Shared Drive MVP: open the Shared Drive and copy the ID from the URL. Leave `''` for My Drive.
5. Run **`setup`** → allow permissions ("Google hasn't verified this app" → *Advanced → Go to HistoryMemo*; normal for your own script).
   Copy **GAS_SECRET** from the log. `setup` also creates the hourly reminder trigger.
6. **Deploy → New deployment → Web app** · Execute as **Me** · Access **Anyone** → copy the URL ending in `/exec` = **GAS_URL**.
   After every code change: *Deploy → Manage deployments → ✏️ → Version: New version*.

## 3b · AI questions, transcripts and book chapters (optional)

In Apps Script → ⚙ **Project Settings → Script properties → Add**:

| Property | Enables | Get it at |
|---|---|---|
| `ANTHROPIC_API_KEY` | Step 2 life-timeline questions (Claude) + AI-written book chapters | <https://console.anthropic.com> → API keys |
| `OPENAI_API_KEY` | Automatic transcripts of English/Vietnamese/Japanese answers (hourly) | <https://platform.openai.com> → API keys |
| `CLAUDE_MODEL` (optional) | Model name, default `claude-sonnet-5` | |

Without keys everything still works: after the 56 questions it goes straight to the diary, and the book lists the
recordings without transcripts. **Teochew answers can't be transcribed automatically** (no speech-to-text model supports
it yet). The family can type a transcript into `stories.json` or the book Doc. Transcripts also make the AI questions
more personal ("You mentioned your mother's bánh tét…"). The keys stay in Apps Script, never on the phone.
Story text is sent to Anthropic/OpenAI: say so in your consent screen (see ROADMAP).

## 3c · Question Sheet, family questions and AI follow-ups

Each storyteller gets a Google Sheet **`Questions – <name>`** in their Drive folder. Family emails on the admin page are
added as **editors**.

| Tab | Who writes | What it does |
|---|---|---|
| **Add questions** | Family | Type a question in **any language** (optionally a life stage and your name). Within the hour (or *🔄 Sync Sheet now* on the admin page) it is translated into English/Vietnamese/Japanese, checked against every question already asked or planned, and **asked next**. The Status column says `Queued`, `Next`, `Answered …` or `Already planned / answered`. |
| **All questions** | HistoryMemo (rewritten each sync) | What's next, everything answered (date, language, recording link, transcript), skipped questions, and the questions still to come. Family may **edit or type the Transcript** (e.g. for Teochew), or type **`Ask again`** in Status to re-ask a question. |

The admin page also has an **＋ Ask** box per storyteller, which does the same as the Sheet.

- **No repeats:** a question is asked once. Skipped questions are not asked again. Only "Ask again" brings one back.
- **AI follow-ups** (needs `ANTHROPIC_API_KEY` + transcripts): about 2 minutes after a story, Claude reads the transcript
  and *may* queue **one** gentle "tell me a little more" question in the same language, using Chris Voss–style tactical
  empathy (a label or mirror, then one *What/How* question, never *Why*). It's asked next, shown with "You talked about: …",
  and saved next to the story it continues (book and film too).
- **Not overwhelming:** a follow-up takes the place of a normal question (never an extra one), at most **1 a day** and
  **2 deep** per story. Closed, sad or very short answers get none. Two skips in a row pause follow-ups for 3 days.
  The storyteller always has **Skip this question** and **That's enough for today** (no more reminders that day).
  Turn follow-ups off per person on the admin page (*Edit*). Limits are in `CONFIG` in `Code.gs`.
- Without `ANTHROPIC_API_KEY`, family questions are translated with Google Translate and only exact repeats are caught.

After updating `Code.gs`, paste the new `appsscript.json` too (it adds the Sheets and trigger permissions) and run
**`setup`** once more to approve them, then create a *New version* of the web app.

## 4 · "Sign in with Google" (OAuth Client ID)

1. <https://console.cloud.google.com> → create project `HistoryMemo`.
2. **APIs & Services → OAuth consent screen**: External, app name HistoryMemo, your email. Scopes: none needed (just email/profile).
   While in *Testing*, add yourself and family as **test users** (up to 100). *Publish* later for anyone.
3. **Credentials → Create credentials → OAuth client ID → Web application**
   - Authorized JavaScript origins: `http://localhost:3000` and `https://historymemo.vercel.app`
4. Copy the **Client ID** = `GOOGLE_CLIENT_ID`.

## 5 · GitHub + Vercel (auto-deploy on every push)

**Push from VS Code**
```bash
git init && git add . && git commit -m "HistoryMemo v0.2"
```
Source Control → **Publish Branch** → *Publish to GitHub private repository* → name `historymemo`.

**Connect Vercel to GitHub** (one time)
1. <https://vercel.com/signup> → **Continue with GitHub** → allow the Vercel GitHub App on the `historymemo` repo.
2. **Add New → Project → Import** `historymemo` → Framework preset **Other** (settings come from `vercel.json`) → **Deploy**.
   Project name `historymemo` gives `historymemo.vercel.app` if the name is free (otherwise rename in Settings → Domains).
3. `npm run vapid`: copy the two notification keys.
4. **Settings → Environment Variables**, tick *Production* and *Preview*: `GAS_URL`, `GAS_SECRET`, `GOOGLE_CLIENT_ID`,
   `ADMIN_EMAILS`, `ADMIN_KEY`, `SESSION_SECRET`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`
   → **Deployments → ⋯ → Redeploy**.

**How it works from then on**
- `git push` to **main** → production deploy at `historymemo.vercel.app` (about 30 s).
- Any other branch / **pull request** → its own **Preview URL** posted on the PR; GitHub Actions (`.github/workflows/check.yml`) runs `npm test`.
- Preview URLs change per deploy, so *Sign in with Google* only works on production and `localhost`; on previews use private links and `ADMIN_KEY`.
- Apps Script is **not** deployed by Vercel: after changing `apps-script/*.gs`, paste/`clasp push` and create a *New version* (README §3).
- Optional CLI: `npm i -g vercel && vercel link && vercel env pull .env.local` → `npm run dev` uses the same variables as Vercel.

## 6 · Set up a storyteller's iPhone (5 minutes)

1. Admin page → **Add storyteller** (name, how the family calls them, languages, rotation, questions per day, video/voice)
   → copy the private link or show the QR code. Or the person simply taps **Continue with Google**.
2. On the iPhone open the link in **Safari** → **Share ⬆︎ → Add to Home Screen → Add**.
3. Open the new **HistoryMemo** icon → choose languages → **Turn on reminders → Allow**.
4. Admin page → **Send test notification**.

iPhone notifications need iOS 16.4+ and only work from the Home-Screen icon (Apple rule).

## 7 · Teochew questions

No phone, Google or Apple voice speaks Teochew, so on the admin page choose **Teochew** and record each question in a family
voice (start with this week's). Until a question is recorded, the screen shows it in the app language with
"Answer in Teochew". English/Vietnamese/Japanese are read aloud by the phone automatically.

## 8 · Make the book and the video book

- **Book:** admin page → **📖 Make book** (or **✍️ Book with AI-written chapters**) → *Open book*. In Google Docs:
  *File → Download → PDF / Word*, or print. Re-run any time; the old version is replaced.
- **Video book** (on your Mac):
  1. `brew install ffmpeg`
  2. Install **Google Drive for desktop** and make the `HistoryMemo` folder available offline.
  3. `npm run video-book -- --folder "$HOME/Library/CloudStorage/GoogleDrive-<you>/My Drive/HistoryMemo/Ba (s1a2b3c4)" --lang vi`
  4. The film appears in that folder as `video-book-vi.mp4` (1280×720). Try it locally first on
     `local-data/drive/Shared drive/HistoryMemo/Demo (…)` after `npm run dev:mock`.

## Where are recordings stored? What if an upload breaks?

1. While recording, the video/voice is held in the phone's memory (it is **not** saved to the camera roll).
2. On **Send**, it is first saved inside the app on the phone (IndexedDB), then uploaded **straight to Google Drive**
   in 4 MB pieces. Nobody uploads anything by hand.
3. **It continues where it stopped.** The phone remembers the Drive upload session. If Wi-Fi drops or the app is closed,
   the next time the app opens (or the connection comes back) it asks Drive how much arrived and sends only the rest.
   iPhone web apps can't upload while closed, so this happens on the next open.
4. The phone copy is deleted only after the server has logged the story. Sending the same story twice is harmless.
5. The server also keeps track (`plan.json` → `uploads`, and the Sheet shows *Still on the phone*):
   - the file reached Drive but the phone never reported back → the hourly check finds it and logs the story (*recovered*);
   - nothing arrived after 7 days (phone lost, app deleted) → marked *Lost on the phone*. The question was never counted
     as answered, so it is simply **asked again**;
   - a recording later disappears from Drive (deleted, trashed) → the daily 3:00 check asks that question again.
